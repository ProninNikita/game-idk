# World Generation

Status: `Draft`

## Goal

The world should support exploration, survival, and automation. It does not have to be infinite at the start, but it should feel large enough for bases and expeditions to matter.

## MVP Approach

Recommendation: deterministic seed + chunk-based generation.

- Seed defines the base world.
- Chunks generate when entering a radius.
- Player changes are saved as diffs.
- Important locations are generated by rules, but can be placed with authored logic.

For the very first prototype, a handcrafted test map is acceptable, but the API should be designed as if the world will become chunked.

## Sizes

Starting numbers:

- tile size: 16 or 32 px, choose after an art test;
- building grid: 1 tile or 2x2 tile footprint depending on visual scale;
- chunk size: 32x32 or 64x64 tiles;
- safe start radius: 2-3 chunks.

## World Layers

- ground terrain;
- biome overlay;
- obstacles/resources;
- water/shore;
- buildings;
- loose items;
- light/heat influence;
- navigation/collision.

## MVP Biomes

### Meadow/Start

Role:

- safe start;
- wood, berries, fiber, stone;
- low threat.

### Forest

Role:

- lots of wood/fiber;
- worse visibility;
- stronger night threats;
- seed/plant resources.

### Rocky Field

Role:

- stone/ore;
- less food;
- more open space for outposts.

### Wetland or River Edge

Role:

- water;
- farming gate;
- slower movement;
- special plants.

After MVP, possible additions: desert, snow, ruins, fungal caves, ashland.

## Resource Distribution

Rules:

- starting area contains everything for Tier 0;
- ore should not be too far away for the first furnace;
- rare resources should require expeditions;
- biomes should create tradeoffs, not just reskins.

## Points of Interest

POIs create goals:

- abandoned camp;
- broken machine;
- old shrine/research point;
- rich ore node;
- safe cave entrance;
- strange growth;
- ruined power relay.

POIs should be readable from a distance through silhouette, light, color, or sound.

## Roads and Routes

The start can work without roads. If the map is large, natural routes are useful:

- forest paths;
- riverbanks;
- passages between cliffs;
- clearings toward POIs.

The player should later be able to build roads, so the base physically changes the world.

## Creature Navigation

MVP:

- simple movement toward the player/target;
- avoid blocked tiles;
- basic `AStarGrid2D` for local pathfinding.

After MVP:

- different navigation weights by biome;
- reaction to light;
- attacks against weak buildings;
- migration.

## World Persistence

Do not save the whole generated world. Save:

- seed;
- visited chunks;
- modified tiles;
- removed resource nodes;
- placed buildings;
- entity states for important objects;
- discovered POIs.

If the generator changes, old saves can break. After a public build, the project needs migration strategy or fixed generator versions.

## Generator Version

Each world stores:

- `world_seed`;
- `generator_version`;
- `created_with_game_version`;
- `schema_version`.

When the generator changes:

- old worlds can use the old generator path;
- or the world can be migrated;
- or saves can be marked incompatible before early access.

## Top-Down Readability

Problems:

- trees hide the player;
- tall objects cover buildings;
- resource nodes look too similar;
- at night, the player cannot see the threat source.

Solutions:

- fade/highlight objects above the player;
- clear silhouettes;
- outlines for interactables;
- light radius with soft edges;
- shadows must not hide important gameplay states.
